# Розділ 5. Керівництво користувача (під розгортання на Render)

Цей текст узгоджений із фактичними маршрутами `core/urls.py`, головним `diploma_project/urls.py` (один веб-сервіс: UI + `/api/` + OAuth2 `/o/` на **одному** хості) та `render.yaml` (сервіс **Web**, `gunicorn … wsgi:application`).

**Базова адреса продакшену:** `https://<ім’я-сервісу>.onrender.com`  
(у кабінеті Render → ваш сервіс → **URL**; у прикладі нижче заміни на свій.)

**Мовний префікс:** сторінки інтерфейсу відкриваються як **`/uk/...`**, **`/en/...`**, **`/de/...`** (перемикач мови у шапці сайту). API та OAuth2 **без** префікса мови: **`/api/...`**, **`/o/...`**.

---

## 5.1 Реєстрація, автентифікація та верифікація

### 5.1.1 Реєстрація облікового запису

1. Відкрий у браузері **`https://<ваш-сервіс>.onrender.com/uk/`** (або `/en/`).  
2. У верхній панелі натисни **Register** / **Реєстрація** — маршрут **`/uk/register/`** (або `/en/register/`).  
3. Заповни поля форми: **ім’я користувача**, **пароль** (двічі), за наявності — **email**.  
4. Підтверди реєстрацію. Після успіху ти будеш автентифікований або перенаправлений на вхід — залежно від логіки форми.

### 5.1.2 Вхід (автентифікація)

1. Відкрий **`https://<ваш-сервіс>.onrender.com/uk/login/`**.  
2. Введи **username** і **password**.  
3. Натисни **Login** / **Увійти**.

**Обмеження частоти:** після багатьох невдалих спроб з **одного** логіна за короткий час сервер може відповісти **429 Too Many Requests** — зачекай до хвилини або перевір пароль.

### 5.1.3 Вихід

1. У меню обери **Logout** / **Вийти** — **`/uk/logout/`**.

### 5.1.4 Профіль

1. Відкрий **`/uk/profile/`** (посилання на ім’я користувача в шапці).  
2. Переглянь **роль** (цивільний / військовий / адміністратор), **статус верифікації**, контактні поля, за потреби — фото профілю.

### 5.1.5 Верифікація особи

1. Відкрий **`/uk/verify-identity/`** (або перейди з підказок у профілі).  
2. Завантаж файли згідно підказок (наприклад, скан документа у дозволених форматах).  
3. Надішли форму. Статус у профілі: **не подано → на перевірці → підтверджено / відхилено**.  
4. Поки верифікація **не підтверджена**, створення запиту допомоги **блокується** (перенаправлення з поясненням).

### 5.1.6 Персонал (staff)

Якщо обліковий запис має права **staff**, у меню з’являється пункт **Staff** → **`/uk/staff/`** (панель модерації та адміністрування). Звичайним користувачам ці URL недоступні (**403**).

## 5.2 Робота з запитами, внесками та модерацією

### 5.2.1 Навігація

У шапці сайту доступні зокрема:

- **Requests** — **`/uk/requests/`** (список запитів, фільтри за статусом / прогресом);  
- **Dashboard** — **`/uk/dashboard/`** (після входу);  
- **My requests** — **`/uk/my-requests/`**;  
- **My offers** — **`/uk/my-offers/`** (ваші внески як волонтера);  
- **New request** — **`/uk/create/`** (лише для автентифікованих; потрібна верифікація);  
- **Messages** — **`/uk/messages/`** та **`/uk/messages/<id>/`** (переписка).

### 5.2.2 Перегляд і створення запиту

**Список:** **`/uk/requests/`** — картки запитів; натисни заголовок для переходу на **`/uk/requests/<id>/`**.

**Створення:** **`/uk/create/`** — назва, опис, категорія (цивільна / військова згідно правил ролі), кількість, доставка (країна; для України — Нова Пошта / Укрпошта / ручний опис залежно від полів форми). Після збереження — перехід до списку або картки запиту.

**Редагування та закриття (власник запиту):** на картці **`/uk/requests/<id>/`** — блок **Owner actions**: **Edit request** (`/uk/requests/<id>/edit/`), форма **Close request** (`POST` на **`/uk/requests/<id>/close/`**) з причиною закриття.

### 5.2.3 Внески (волонтер)

1. На **`/uk/requests/<id>/`** (ти не власник) — блок **Propose a contribution** — форма **`POST`** на **`/uk/requests/<id>/contribute/`**.  
2. Вкажи кількість і точку відправлення (НП/Укрпошта або опис для не-UA).  
3. Після відправки пропозиція має статус **очікує рішення власника**.

**Власник запиту** на тій же сторінці в блоці вхідних пропозицій бачить кнопки **Accept**, **Request changes**, **Decline** — форма **`POST`** на **`/uk/contributions/<id>/owner-action/`** з полем `action` = `accept` / `request_changes` / `decline` та опційною **note**.

### 5.2.4 Після прийняття внеску

У **My offers** (`/uk/my-offers/`) для прийнятого внеску доступні зокрема:

- **Shipping slip + QR** — **`/uk/contributions/<id>/shipping-slip/`**;  
- **Upload proof** — **`/uk/contributions/<id>/upload-proof/`**;  
- **Chat** — перехід у **`/uk/messages/<conversation_id>/`**;  
- **Dispute** — **`/uk/contributions/<id>/dispute/`**;  
- **Update proposal** / **Withdraw** — за наявності кнопок у статусі пропозиції.

### 5.2.5 Скарга на запит

На картці запиту — дія **Report** → **`/uk/requests/<id>/report/`** (форма причини). Запис потрапляє в чергу модерації.

### 5.2.6 Панель персоналу (`/uk/staff/`)

Після входу під **staff**:

- **`/uk/staff/moderation/`** — скарги;  
- **`/uk/staff/verifications/`** — черга верифікацій;  
- **`/uk/staff/requests/`**, **`/uk/staff/contributions/`**, **`/uk/staff/disputes/`** — керування сутностями;  
- **`/uk/staff/users/`**, **`/uk/staff/admins/`** — за потреби.

Дії виконуються кнопками на відповідних сторінках (підтвердження, приховування, зміна статусу тощо).

### 5.2.7 Адміністратор Django

**`/uk/admin/`** — стандартна адмінка (створення OAuth2 **Application**, користувачі, записи аудиту тощо). Доступ лише для користувачів з прапором **staff/superuser**.

## 5.3 Робота з API (той самий хост, що й UI)

База: **`https://<ваш-сервіс>.onrender.com`**

| Ресурс | Шлях |
|--------|------|
| REST API | **`/api/`** (наприклад **`/api/requests/`**, **`/api/contributions/`**) |
| JWT (отримання пари токенів) | **`POST /api/auth/jwt/token/`** |
| Оновлення JWT | **`POST /api/auth/jwt/refresh/`** |
| OpenAPI (схема) | **`GET /api/schema/`** |
| Swagger UI | **`GET /api/docs/swagger/`** |
| ReDoc | **`GET /api/docs/redoc/`** |
| OAuth2 (authorization server на цьому ж сервісі) | **`/o/authorize/`**, **`POST /o/token/`**, інші ендпоінти пакета `oauth2_provider` |

### 5.3.1 Заголовок авторизації

```http
Authorization: Bearer <access_token>
```

Токен — або **JWT access** (після п. 5.3.2), або **OAuth2 access token** (після обміну коду на **`/o/token/`**).

### 5.3.2 Отримання JWT

**POST** `https://<ваш-сервіс>.onrender.com/api/auth/jwt/token/`  
**Content-Type:** `application/json`

```json
{
  "username": "your_username",
  "password": "your_password"
}
```

У відповіді скопіюй **`access`**. Приклад (curl):

```bash
curl -s -H "Authorization: Bearer YOUR_ACCESS_TOKEN" "https://<ваш-сервіс>.onrender.com/api/requests/"
```

### 5.3.3 OAuth2 на Render (один хост)

1. Увійди в **`https://<ваш-сервіс>.onrender.com/uk/admin/`** → розділ **Applications** (django-oauth-toolkit).  
2. Створи застосунок: тип клієнта, **redirect URI** (наприклад `https://<клієнт-або-той-самий>.onrender.com/...` або локальний URI для тестів), scopes.  
3. Отримай **client_id** (і **client_secret**, якщо confidential).  
4. Відкрий у браузері **`https://<ваш-сервіс>.onrender.com/o/authorize/`** з параметрами `response_type=code`, `client_id`, `redirect_uri`, `scope` — після логіну та згоди отримаєш **`code`** у query рядка редиректу.  
5. **POST** `https://<ваш-сервіс>.onrender.com/o/token/` з полями `grant_type=authorization_code`, `code`, `redirect_uri`, `client_id` (+ `client_secret` для confidential).  
6. У відповіді візьми **`access_token`** і використовуй у **`Authorization: Bearer ...`** для **`/api/...`**.

Деталі параметрів див. офіційну документацію OAuth2 та підказки на сторінці **`/o/`** (індекс посилань, якщо налаштовано).

### 5.3.4 Приклади викликів REST

Уточни операції в **Swagger** (`/api/docs/swagger/`). Типово:

- **GET** `/api/requests/` — список (для аноніма — без прихованих/закритих згідно логіки API);  
- **GET** `/api/requests/<id>/` — деталі;  
- **POST** `/api/requests/` — створення (потрібен Bearer + верифікований профіль);  
- **POST** `/api/requests/<id>/close/` — закриття (власник або staff);  
- **GET/POST** `/api/contributions/` та **`…/owner_action/`** — внески та рішення власника (див. схему в Swagger).

Усі тіла та коди відповідей звіряй з інтерактивною документацією — вона відповідає коду `RequestViewSet` та `ContributionViewSet`.

Наведено керівництво користувача для **продакшен-розгортання на Render**: один HTTPS-хост з інтерфейсом під префіксами **`/uk/`**, **`/en/`**, **`/de/`**, REST API під **`/api/`** та OAuth2 під **`/o/`**. Описано реєстрацію, вхід, профіль, верифікацію, роботу з запитами та внесками, повідомлення, скарги, панель **staff** та використання **JWT** і **OAuth2** для програмного доступу до API з посиланням на **Swagger/OpenAPI**.

## Загальні висновки (для розділу «Висновки» пояснювальної записки)

Розроблено та розгорнуто прототип веб-системи координації гуманітарної допомоги з верифікацією користувачів, обліком запитів і внесків, модерацією та REST API з документуванням OpenAPI. У конфігурації **Render** використовується один веб-сервіс (`render.yaml`): **HTTPS**, PostgreSQL через `DATABASE_URL`, статичні файли після `collectstatic`. Реалізовано JWT та OAuth2 на спільному хості з UI, обмеження частоти запитів для типових точок зловживання, заголовки безпеки та журнал аудиту. Працездатність підтверджено автоматизованими тестами (`core/tests.py`). Напрями розвитку: окремий сервіс авторизації за потреби масштабу, спільний Redis для rate limit у кластері, розширення інтеграційних тестів.
